# Module 2.3 Insecure Deserialization in Flask (with Malicious Payload)**


In this exercise we will learn how insecure deserialization can be exploited and how attackers can inject malicious code via serialized objects.


You can find the code for a  Flask app that accepts session data, serializes it, and stores it in a cookie. This app is **insecurely deserializing** the session data, making it vulnerable to attacks.

## **Explanation of the Vulnerable Code:**

- The `/set_session` route creates a **normal session** with a `username` and serializes it using `pickle`.
- The session data is **base64-encoded** and stored in a **cookie** called `session`.
- The `/get_session` route retrieves the `session` cookie, **deserializes** the data, and displays the `username`.


We also have a script to generate a malicious payload that will trigger arbitrary code execution during the deserialization process.



## **Run the Vulnerable Flask App**


### Run the Flask app:
   ```bash
   python insecure_deserialization.py
   ```

The server should start running at `http://127.0.0.1:5000/`.
### Create a normal session first: 

Run the following curl command to create a normal session, which will store the session cookie in cookies.txt:
```bash
curl -X POST -d "username=user" http://127.0.0.1:5000/set_session -c cookies.txt
```

## **Generate the Malicious Payload**

Run the `malicious_payload.py` script to generate the **malicious session cookie**.

```bash
python malicious_payload.py
```

You should see an output similar to this:

```
Malicious Session Cookie: gASV... (long base64 string)
```

### ** Replace the Session Cookie**

Open the `cookies.txt` file that you generated when you first created a session (using the `curl` command). If you haven't created one, just use the `curl -X POST` command to generate a session as shown earlier.

Replace the **normal session cookie** with the malicious session cookie that was generated by `malicious_payload.py`.

Replace:

```
session   <normal_base64_session_string>
```

with:

```
session   gASV... (your malicious base64 string)
```


## **Test the Malicious Cookie**

Now, use the `curl` command to send the malicious session cookie and test if the application executes the malicious payload.

```bash
curl -b cookies.txt http://127.0.0.1:5000/get_session
```

---

### **Expected Outcome:**

- When the Flask app deserializes the malicious session, it should trigger the code execution and print `"Hacked!"` in the terminal running the Flask app.
- The browser will show a message like `Hello, user!`, and you should see the `"Hacked!"` output in your terminal, showing that the exploit was successful.



## **Fix for Insecure Deserialization:**

The main fix for this vulnerability is **never deserializing untrusted data**, especially with modules like `pickle` that can execute arbitrary code during deserialization. Instead, you can use a more secure serialization format like **JSON** or use **signature-based validation** to ensure that the data is safe to deserialize.
